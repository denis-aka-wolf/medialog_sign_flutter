# Medialog Sign (Windows Desktop prototype)

Демонстрационный Flutter-проект для управления пользователями, тестовыми сертификатами и правами подписи документов.

## Требования

- Flutter SDK с поддержкой Windows Desktop
- Visual Studio 2022 с workload **Desktop development with C++**
- Windows 10/11

## Запуск

Откройте терминал в папке проекта и выполните:

```powershell
flutter doctor
flutter config --enable-windows-desktop
flutter pub get
flutter create --platforms=windows .
flutter run -d windows
```

`flutter create --platforms=windows .` создаёт служебные файлы платформы Windows, которых нет в исходном архиве, чтобы проект не зависел от конкретной версии Flutter SDK.


### Сборка релиза

Откройте терминал в папке с проектом и выполните команду для компиляции в релизном режиме:
```powershell
flutter build windows --release
```

После завершения сборки готовый исполняемый файл .exe, необходимые .dll и папка с ресурсами (data) появятся по пути:
```text
build\windows\x64\runner\Release
```
(или build\windows\runner\Release в зависимости от версии Flutter).

## Что реализовано

- Панель состояния с тестовой статистикой.
- Пользователи: поиск, выбор сотрудника, активность, право подписи произвольных файлов.
- Управление тестовыми сертификатами: назначение, просмотр отпечатка и срока действия, демонстрационная регистрация.
- Демонстрация копирования ЭЦП между пользователями с журналом этапов.
- Подписание: выбор файлов через стандартный диалог Windows, выбор типа подписи, демонстрационный результат без создания фальшивого `.sig`.
- Документы: история демонстрационных операций и фильтрация.
- Нетрика: подготовка демонстрационного задания для пациента.
- Журнал операций.
- Настройки интеграций со статусом «не подключено».
- Сброс тестовых данных.

## Важные ограничения прототипа

Все сведения о пользователях, сертификатах, правах, документах и операциях — фиктивные и хранятся в памяти. При перезапуске изменения сбрасываются.

Прототип **не** подключается к MS SQL или Медиалог, не вызывает КриптоПро CSP, не копирует закрытые ключи, не меняет PIN-коды, не устанавливает сертификаты и не формирует настоящие криптографические подписи. `.sig`-файлы намеренно не создаются, чтобы тестовый результат нельзя было принять за действительную подпись.

В реальной версии нужно отдельно спроектировать безопасный Windows-компонент для КриптоПро, права доступа к ключам, аудит, обработку PIN-кодов и интеграцию с Нетрикой. Не храните PIN-коды и закрытые ключи в базе данных или журнале операций.
